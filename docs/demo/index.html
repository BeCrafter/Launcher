Login Items
Login Items 是 macOS 系统设置管理的登录时启动项，与 launchd 的 LaunchAgent 机制相互独立。
与 LaunchAgent 的核心区别
LaunchAgent由 launchd 管理，plist 驱动，支持定时/监听/保持存活，可通过 launchctl 精细控制
Login Item由 SMAppService 管理，仅"登录时启动"语义，通过系统设置 UI 控制
UI 重构方案 A–E
五个方向的重构计划，以「plist 是 launchd 唯一事实来源」为核心理念，基于现有功能优化，分阶段可独立发版。
重构 A — 共享 UI 原语
提取 RowCard、StatusDot、PendingActionButton、FilterChipBar、CopyButton、HomebrewPalette 六大原语，消除重复。
重构 B — 结构化 plist 编辑器
将 formManagedKeys 扩展至覆盖全量 launchd schema，让 UI 直接反映 plist 结构。
重构 C — ManagedTask 协议
抽象统一 "受管任务" 协议，RowCard 与 PendingActionButton 真正泛型复用。
重构 D — 统一错误/反馈层
errorMessage Binding 抽为 ToastCenter 环境对象，统一 Toast / ErrorOverlay 展示机制。
重构 E — 侧边栏与编排收尾
修复 Services sidebar badge、.brewServicesDidChange 通知替换、模块切换 searchable 提示统一。
建议实施阶段
1
阶段一：重构 A + D（共享原语 + 错误层）
只提取重复，不改业务逻辑。风险低，可快速发版。
风险低可发版无逻辑变更
2
阶段二：重构 B（结构化 plist 编辑器）
核心价值所在。先补 PlistService / LaunchItem 现有键往返测试，再扩键。
风险中可发版需补测试
3
阶段三：重构 C（ManagedTask 协议统一）
抽象受管任务协议，Crontab 作为 ops 子集不同的实现纳入同一容器。
风险中可发版
4
阶段四：重构 E（侧边栏收尾）
修复 Services badge、替换跨 store 通知机制、统一模块搜索提示。
风险低可发版
